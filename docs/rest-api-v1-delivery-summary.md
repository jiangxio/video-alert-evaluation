# REST API v1 改造交付说明

## 一句话总结

为平台新建了一套 `/api/v1` REST 接口，与旧接口并行运行（旧接口保留、自动标记弃用）。覆盖视频、告警、告警 OCR 三大功能域共 **35 个接口**，配套 **91 项接口测试 + 17 项回归快照**，全量测试 **170 项通过、0 失败**。

## 关键设计（大白话）

| 设计 | 说明 |
|---|---|
| **统一返回格式** | 所有接口返回 `{code, message, data}`。成功 code=0；失败 code=HTTP 状态码（404/400 等），并可带 `error_code` 精确区分错误类型（如 `DATASET_NOT_FOUND`） |
| **复用旧接口逻辑** | 新接口不重写业务，而是调用旧接口函数 + 包装成统一格式。二进制（文件下载/图片）原样透传，不套格式 |
| **旧接口不动** | 旧接口全部保留、逻辑不改。全局钩子自动给旧接口加 `Deprecation: true` 弃用头，引导迁移 |
| **错误处理分流** | `/api/v1/` 路径的错误返回统一格式；其他路径保持原有行为（页面 404 等），互不影响 |
| **字段白名单** | 修改接口（PATCH）严格只开放应有字段，传其他字段返 400 拒绝，防止误改 |
| **批量操作用 :action** | 非增删改查的操作用冒号后缀命名，如 `:batch-add`、`:batch-delete`、`:import`，避免与资源 ID 冲突 |
