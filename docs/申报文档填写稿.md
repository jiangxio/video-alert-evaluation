## 一、评测工具具体描述

### 1. 工具介绍

流智评面向视频流AI算法常态化评测。通过对视频添加水印（视频ID+时间戳），OCR提取告警图片水印信息，与人工标注真值做时间窗口自动对齐，计算精确率、召回率、平均误检数/小时。覆盖任务创建→样本导入→评测计算→结果输出→报告生成全流程闭环，支持Docker一键部署。

### 2. 功能特色

- **水印基准法自动对齐**：为视频打水印（视频ID+时间戳），OCR提取告警图水印即可与真值事件自动对齐，免去人工逐帧标注。
- **视频流时序评测**：以±5s容差时间窗口做告警与真值事件匹配，判定命中/误检/漏检；按事件类型计算精确率、召回率、平均误检数/小时。
- **全流程闭环**：任务创建→样本导入→评测计算→结果输出→报告生成，全流程贯通。
- **评测结果可视化**：多维度展示命中/误检/漏检分布与时间轴，GT事件得分（绿/橙/红）直观呈现召回情况。
- **分事件类型指标**：按事件类型分别展示精确率、召回率、误检，支持人工复核与状态覆盖。
- **告警复核台**：多模态辅助对告警图检测结果进行审查，支持人工确认与改判。
- **自动标注**：选择事件类型，多模态对视频自动标注事件区间，降低人工标注成本。
- **AI 助手**：自然语言驱动评测全流程，说一句话完成打水印、自动标注、推流、启动评测、导出报告等操作。
- **AI生成详细报告**：一键生成自包含评测报告，含测试摘要、结论与改进建议，可存档汇报。
- **多算法版本管理与对比**：注册算法版本，同一评测集对比不同版本指标，支撑选型与回归。
- **推流模拟**：RTSP推流到MediaMTX，模拟真实视频流做实时评测。
- **三种交互方式**：命令行、REST API、Web可视化页面，覆盖自动化集成与人工操作。
- **Docker一键部署**：一键启动双服务，内置全部依赖、离线可用，仅需改一个配置文件。
- **独立视觉评测模块**：支持目标检测与图像分类评测，含数据集标注、跨数据集质检与版本管理，与视频流评测解耦（独立服务/端口）。
- **评测结果确定性**：基于确定性匹配，重复评测5次偏差0%；与人工验收基准对比MAPE<1%。

### 3. 使用场景与部署方式

**适用评测场景**：

1. **准入测试**：算法上线前，对真实视频流跑全量评测，验证精确率/召回率/误检频率是否达标。
2. **版本回归测试**：算法版本迭代后，对比新旧版本指标，防止回归。
3. **多算法对比选型**：同一评测集跑多个算法版本，横向对比指标择优。
4. **常态化评测**：周期性评测已上线算法，监控质量衰减。
5. **模型能力评测**：评估算法在光照变化、遮挡、角度切换等真实场景下的鲁棒性。
6. 覆盖**视觉类**评测（视频事件检测、视觉异常检测、目标检测、图像分类，图像分类由独立视觉评测模块支持）。

**部署方式**：

1. 灵活便捷：Docker Compose 一键启动，无需复杂环境依赖（全部依赖内置），参赛现场可能无外网时离线可用。
2. 快速接入：仅需修改 `.env` 一个配置文件（API 密钥），无需专业技术团队全程支撑。
3. 标准化：命名卷持久化数据，重建容器不丢数据；告警类型与算法配置支持覆盖。

### 4. 技术创新性与自主性

**创新立论：为什么基于视频流，以及水印基准法解决了什么。**

视频流算法运行在连续视频流上，其事件触发依赖前后帧时序、多算法协同与防抖动等时序配置——单张图片脱离真实运行环境，无法触发与体现这些能力，因此评测视频流算法必须基于视频流，让算法在真实时序下运行并产出告警。

但基于视频流评测有一个核心难点：算法对视频跑出的告警图本身不携带视频位置信息，**若不将告警对齐到真值事件，只有一堆告警图，无法获知漏告多少，评不了召回率**（这与传统图片评测不同——图片测试集只要预先标注就能评召回率）。要评召回率，必须把每张告警图对应回视频中的事件位置。

传统做法靠人工逐张将告警对齐到标注事件，成本高、主观、不可复现。本工具以水印基准法解决此难题（见下"关键技术"），实现告警与真值的自动时间对齐，同时得出精确率、召回率与漏检，对齐全自动、客观可复现。

**关键技术**：水印基准法——用 FFmpeg drawtext 为视频添加"视频ID|时间戳"水印，被测算法对水印视频运行产出告警图片，OCR 提取水印中的视频ID与时间戳，即可将告警自动对齐到人工标注的真值事件区间。相比传统逐帧人工标注对齐，大幅降低标注成本且对齐客观可复现。

**技术创新点**：

1. 水印基准法实现告警与真值的自动时间对齐，免去逐帧人工标注。
2. 评测计算基于确定性匹配，结果可复现、偏差0%。
3. 视频流时序评测指标体系（精确率/召回率/误检小时，按类型宏平均）。
4. 评测工具在自身命题场景下的创新性优化：CPU纯OCR离线运行、低资源消耗。

**为何不直接用摄像头自带 OSD，而要主动打水印？** 许多摄像头视频自带 OSD（叠加的摄像头ID+时间），理论上可直接 OCR 识别做对齐。但 OSD 存在两个不可接受的缺陷：一是**不可控、不规范**——每个摄像头品牌的 OSD 位置、字体、格式各异，通用 OCR 识别率低，需逐摄像头适配，工程上不可行；二是**无法支撑可重复测试**——以各异的 OSD 为基准，不同视频的对齐基准不统一，跨算法、跨版本结果不可比。而回归测试、版本对比正是评测工具的核心场景，其前提是对齐基准统一可控。本工具主动以 FFmpeg 注入水印，固定字体、位置与格式，OCR 可针对性预处理、识别可靠，所有视频基准一致，**保证同一视频可被重复测试、结果可复现可比**——这是依赖现成 OSD 做不到的。

**自主性**：

- 具备完整自主研发能力，全部源码及技术文档可完整提交。
- 核心模块（水印生成、OCR预处理、评测计算、指标统计、报告生成）均为自主研发。
- 基础框架采用开源组件并遵循开源协议：Flask（Web）、EasyOCR（OCR）、Playwright（PDF渲染）、FFmpeg（视频处理）。

### 3. 评测指标体系

**评测参数**：合并间隔 5.0s / 事件间隔 8.0s / 时间容差 ±5s / 触发率 0.9

**评测流程**：算法对水印视频运行产出告警图 → OCR 解析告警图水印，提取视频ID与时间戳 → 将时间戳与 GT 事件区间比对（±5s 容差窗口）→ 计算精确率、召回率、平均误检数/小时。

**核心定义**：

- **命中**：告警时间戳落在 GT 事件区间 ±5s 容差范围内（告警时间窗口与 GT 容差区间存在重叠即判定命中）
- **误检（FP）**：产生告警但未命中任何 GT 事件区间
- **漏检（FN）**：GT 事件区间内无任何匹配告警
- **告警合并**：同一视频、同一事件类型下，相邻告警时间差 ≤5.0s 合并为一条事件

**指标公式**：

- 精确率 = 正确告警数 / 有效告警总数
- 召回率 = 命中 GT 事件数 / 总 GT 事件数（按事件类型分组后**算术平均**，非加权）
- 平均误检数/小时 = 误检告警数 / 评测总时长（小时）（按事件类型分组后**算术平均**）
- 理论告警数 = (GT 事件时长 / 事件间隔) × 触发率

**验收标准**：整体精确率 ≥ 85%、整体召回率 ≥ 80%、平均误检数/小时 ≤ 10、单事件召回率 ≥ 80%
